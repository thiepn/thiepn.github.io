# H19 — Complete Cross-App Workflows

Home composes three staged workflows under `PUBLIC_HUB_WORKFLOWS_PRIVATE=staged-v1`: thought → Notes, browser reading → study note, and account due review → TMS60. Existing capture, Library and TMS60 staged flags/configuration supply the capabilities. Defaults remain off; workflow staging marks private reads and inline writes in release metadata and fails public-only qualification.

A shared RAM-only coordinator receives validated owner envelopes through direct module calls. There is no private-payload global event bus, DOM payload encoding or second content store. Each preview binds the selected Hub account, exact source context/request, resource and expiry. Confirmation rejects expired, refreshed, revoked, unavailable and wrong-account selections. Source controllers invalidate the coordinator on refresh/clear; hide, identity change, background, navigation and restored navigation clear private previews. Titles render as text. Only reviewed Library/TMS60 destinations are constructed.

Thought capture previews the selected account and Notes / Unfiled destination before opening H18’s recoverable draft. A reading workflow previews title, edition/release, current/furthest progress, checked time and the exact Library resume URL. The user explicitly consents to copying device-local metadata into the selected account’s Notes draft. It never infers that browser history belongs to that account. Existing drafts, unknown save outcomes and stored receipts cannot be overwritten. Only an empty unsent draft accepts the study-note seed. Preparing the draft performs no owner write; the user reviews/edits it, connects capture and separately confirms Save. The draft survives reload and unavailable create permission. H18’s immutable request IDs, durable owner receipts and confirmed-save checks remain authoritative. CFI/chapter details, book bytes, highlights and existing note bodies are not transferred.

After study-note preparation, an exact revision-qualified Library link can resume the source edition in a new tab. The owning resolver checks the edition/release; Hub cannot claim the book loaded or the reader reached a particular position. Full reader content/device qualification remains H20.

Due-review choices come only from a fresh account-bound summary, never recent-practice/search results. The confirmed handoff selects the exact translation, verse and wording/reference dimension. TMS60 opens its native screen and requires explicit practice. The preview explains that its local progress/account may differ from the source cloud snapshot. Hub never marks a review complete or moves progress merely because a link opens. Missing native translations remain an owner error; no fallback translation is invented.

Qualification: 243 Hub unit tests including nine coordinator cases; seven paired browser scenarios with actual Hub/Account builds, the actual Library metadata bridge and native TMS60 reference screen. OAuth issuance and Notes write replies are simulated in paired tests; H18’s separately verified hosted RPC is reused unchanged.
