O30 adds a DISTINCT original Markdown footnote ordering workflow for long research documents. It inspects an existing terminal group of at least two genuine single-line footnote definitions, presents original citation IDs, definition lines, first actual use lines and counts, and lets the user choose first-use order or alphabetical citation ID order. The result is previewed as a complete original Markdown textarea, with explicit previous and proposed ID sequences. Only confirmation dispatches the original Office textarea input event through its existing IndexedDB v1 CAS/autosave/history. This is NOT a new editor, writer, shadow index, database, or schema.

The source algorithm preserves each original footnote definition text, marker and ID, and replaces only original terminal definition line bodies in place. Mixed CRLF/LF/CR separators, blank lines, headings and surrounding authored content remain unchanged; genuine reference IDs and positions are rechecked after ordering. Unsafe duplicate, blank, control-character, oversized, ambiguous, fewer than two terminal definitions and no-op cases fail closed. Original in-memory preview and owner/document/saved-revision/source/mode guards reject stale user actions; privacy and concurrent CAS protect original ownership. No citation verification or guessed authority. No merge, deploy, migrations, credentials, production writes or manually triggered paid CI.

Original-source and browser tests cover first-use ordering, alphabetic order, Unicode/CRLF and blank gaps, fences, duplicates, no-op, source stale, original save/reload, mobile privacy, concurrent edits.
