# THIEPN Hub Office O26 — original citation-issue provenance

Original draft PR #175, branch `feature/hub-office-o1-native-documents`, exact O25 parent `8fd14f04861655dfbb7cf53d1e270ee5582320ab`.

O26 introduces read-only issue-history review, separate from O19 current problem controls and O21–O25 citation editing/recovery engines. A bounded analyzer reads the actual retained Office v1 Markdown history plus the current saved source and reuses original O19 diagnostics for missing footnote definitions, duplicates, unused footnotes, and broken original heading references. It groups actual occurrences by issue kind and immutable original ID, preserving exact first observed source line/offset and count per retained version. For current problems it distinguishes introduced, persisting and reintroduced; problems absent from the current source are resolved *within available retained snapshots*. It never infers missing earlier revisions, first-ever occurrence, change authorship, external source validity or citation verification.

The original Office reference area offers a review button, unresolved/resolved/all filter, counts, retained revision numbers, current-source jump and original timeline revision handoff. Current source and historical excerpt use only original Office navigators. Reviewer state is in memory, never persisted. Document switches, new source edits, autosave/revision changes, source ownership and mobile privacy masks clear all historical issue details, while original CAS/save/history remain the only writer. Overlong sources, oversized unique issue sets, damaged or duplicated revision identities fail closed rather than truncate.

Focused unit tests cover issue status changes across discontinuous revisions, exact offsets/occurrence counts, CRLF, Unicode, fenced pseudorefs, authentic heading links, bounded identity/version limits. Genuine Chromium/Firefox/WebKit browser regressions check source navigation, resolved reference history, reintroduced issues, reload, source changes and mobile privacy. Account IndexedDB-before-consent and historically observed WebKit token-refresh remain independent release blockers. No merge, deployment, migration, production writes, manually paid CI, credentials or costs.
