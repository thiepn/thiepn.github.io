# Hub CI-02 — Fast development shadow pipeline

## Scope and qualification ordering

Stacked on draft PR #206 at c90669fc81d27639124652834392fc57b6de4061. The parent pins 27 existing workflows, 298 source files, 86 npm commands, 1,206 studio identities and 4 existing skips. CI-02 adds a separate read-only workflow; it does not edit Quality, deploy, integration workflows, package files, tests of application behavior, or branch settings. PR #205 is not a dependency and must remain untouched.

The first job of CI Fast (shadow) checks out the exact CI-01 parent, verifies Git source pins and clean source integrity, runs the native six Node tests, parses the pinned YAML inventory, compares real Playwright discovery with the historical main-push report, builds the original parent, and compares native Chromium execution of the three original calendar-smoke cases. The second job has an explicit needs dependency; it cannot run if parent qualification fails. This is not full browser execution of the parent; the prior exact-main execution remains historical evidence. The initial implementation environment could not clone GitHub; this job is the authoritative first native qualification.

## Deterministic change selection

- PR event: checkout the exact tested merge SHA with full history; diff the event base SHA against that SHA. Both hashes and the baseline pin are printed in evidence. Dispatch: explicit full ancestor SHA. Never accept an abbreviated or shell-interpolated input.
- Parse NUL-delimited Git name/status output including rename/copy source and destination. A changed existing spec is included; all unit tests execute regardless of impact.
- Reviewed existing source paths map to explicit test domains and transitive dependent domains in config/ci/test-impact-v1.json. The policy is validated against the immutable source tree and baseline studio inventory. Unknown, shared, security-sensitive, generated, configuration, added, removed, copied, renamed, or otherwise structural paths demand full Quality. Intervening non-CI changes on the comparison base and discovery drift also require full Quality.
- The mapping is conservative and intentionally incomplete, not an automatically proven static import graph. A shared shell change can affect a large portion of the suite. Office-specific changes include Office browser tests; shared auth/runtime changes fall back. Each selection records reasons and full dependency closure.
- Full fallback uses the two sentinel files in the shadow job, while existing Quality runs the entire suite. It is explicitly labeled FULL_QUALITY_REQUIRED, not equivalent to full execution. A separate full workflow already runs, so duplicating all tests would defeat shadow evaluation. Even TARGETED_SHADOW never authorizes merge or release.
- Every fast run retains owner-release and generated-review boundaries, release source availability, Account CI boundaries, product/runtime/phase validation, full unit tests, generated/source validation, type checking, build and performance budget. Browser setup preserves the original full Chromium channel, all three engines and zero retries.

## Shadow validation and evidence

The selector discovers the entire current studio suite using the real JSON reporter, records parity against CI-01, and independently discovers its exact file-filtered subset. The selected inventory must match the full inventory's selected identities without missing, extra or duplicate cases; every selected file and browser engine must appear. Actual execution must match the selected inventory and all known outcomes; unexpected skips, changed skip reasons, errors, retries and non-passes fail. New identities default to expected pass, never an implicitly approved skip. A discovery mismatch forces full Quality or fails closed if a selected suite cannot be discovered.

The job publishes full-discovery.json, baseline-discovery-parity.json, plan.json, selected-discovery.json, selected-expected.json, selected-execution.json and selected-parity.json under the run's artifact. No report is release evidence. Existing Quality retains independent execution, including its smoke and final release gates. Cross-app, private and live qualifications are not represented as fast passes.

The two final successful plan statuses explicitly say FULL_QUALITY_STILL_REQUIRED. A failed or incomplete job never reaches a passing status. Artifacts are retained seven days. No privileged secrets or private repository checkout.

## Measured reference, not a speed guarantee

From historical main timing (one worker): full studio 1,206 cases, about 41.7 minutes of summed individual test durations. The two fallback sentinels cover 42 cases, approximately 56 seconds of historical case duration. The example workspace-unified-h20.css mapping covers 23 files and 729 cases, about 14.9 minutes historically; the conservative shell closure is deliberately broad. Build, setup, queueing and the CI-01 prerequisite are extra. These are estimates from historical observations, not measured new-pipeline timings. CI-03 parallelization and later measured refinement should improve the broad-shell critical path without dropping final coverage. CI-02 shadow mode deliberately adds work during evaluation; only CI-05 may stop redundant full audits on draft commits.

## Local verification

Run from a clean checkout with full Git history and installed dependencies:
```sh
node --test tests/ci/*.test.mjs
npm run build
npm install --prefix /tmp/audit-tools axe-core@4.13.0
npx playwright install --with-deps chromium firefox webkit
node scripts/ci/fast-shadow.mjs <full-base-sha> <full-tested-sha> /tmp/hub-ci-fast
```

The eight new selector tests cover NUL diff parsing, shell and Office dependencies, shared/unknown inputs, structural changes and drift, determinism, changed test files, and missing/duplicated/extra/browser-less discovery. Existing CI-01 tests are preserved. Actual GitHub Actions native reports, not an isolated fixture evaluation, determine qualification.
