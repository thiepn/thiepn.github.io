## Running the tools

From a clean CI-01 checkout with full baseline history and committed lockfile:

```sh
npm ci --no-audit --no-fund
node --test tests/ci/baseline.test.mjs
node scripts/ci/baseline.mjs verify
node scripts/ci/baseline.mjs inventory > /tmp/hub-ci-inventory.json
node scripts/ci/baseline.mjs timings > /tmp/hub-ci-timings.json
```

Source verify is intentionally CI-01-specific: it rejects any baseline file modification, deletion or out-of-scope additions, a missing base tree and dirty worktree. After subsequent main changes, report drift and create a separately reviewed successor baseline rather than rewriting history.

For a fresh discovery capture (no test execution):

```sh
npx playwright test -c playwright.studio.config.ts --list --reporter=json > /tmp/studio-list.json
node scripts/ci/baseline.mjs compare studio discovery /tmp/studio-list.json
```

For actual execution comparison, use JSON report(s) from exact tested checkout, same build/environment and existing studio configuration, with all three projects and no retries. For example:

```sh
npm run build
npx playwright install --with-deps chromium firefox webkit
npm install --prefix /tmp/audit-tools axe-core@4.13.0
npx playwright test -c playwright.studio.config.ts --reporter=json > /tmp/studio-run.json
node scripts/ci/baseline.mjs compare studio execution /tmp/studio-run.json
```

A split run can provide multiple JSON reports after all shards finish. The comparison requires every expected identity exactly once, rejects unexpected identities, unexpected failures, changed skip reasons, unexpected skips, retries, malformed results and global reporter errors. Formerly skipped cases may become genuine passes. Discovery only checks identities and cannot prove execution. The CLI does not authenticate JSON provenance or bind it to a commit; CI-03 must independently enforce source, build and report provenance in its aggregator. Do not treat a locally fabricated JSON file or historical pass as release evidence. For other browser configurations, enumerate with the corresponding config and `--list --reporter=json` in an appropriate environment; do not execute disabled private suites or add access tokens. Exact identities for those suites require separate discovery evidence before their migration.

Measure a completed workflow from raw GitHub job JSON (all pages required; one page is sufficient when total_count equals returned job count):

```sh
gh api 'repos/thiepn/thiepn.github.io/actions/runs/45708927477/jobs?per_page=100' > /tmp/jobs.json
node scripts/ci/baseline.mjs timings /tmp/jobs.json
```

Runner time sums actual completed non-skipped job intervals; execution span is earliest start to latest completion, not queue latency or billed time. Do not compare failed and passing runs as identical workloads. Record run ID/attempt/commit/build profile with future timings; preserve distinct historical samples. Report aggregation is read-only and not a release credential.
