O18 is a substantial distinct native *authored-content* feature. The existing O3/O16 outline is only a navigation sidebar and cannot insert, update or export a portable Markdown Table of Contents, nor offer source-backed internal heading references. New src/lib/office/toc.ts derives genuine heading IDs from original outlineFor (ignores fenced-code pseudoheadings and the O18 generated TOC block), creates deterministic unique slug IDs for duplicate and multilingual headings, generates bounded source markdown up to 120 authentic headings, and updates exactly one explicitly managed sentinel TOC block. Missing, malformed or repeated sentinels, body-size overflow, ambiguous targets and invalid selections fail closed without changing the editor. Original heading IDs derive from source only; there is no external index or database.

The original deliberately constrained Markdown renderer now emits safe heading id attributes and verified fragment hrefs for #office-ref-* alongside existing safe http(s) links, never interpreting raw HTML or untrusted JavaScript. Browser preview clicking an internal reference focuses the matching original Markdown source heading; exported standalone HTML can use the same anchor markup. Generated TOC sentinel source lines are omitted from visual preview but remain in portable original Markdown.

Native editing actions: Preview TOC insertion or refresh as the complete read-only source; Cancel; explicitly Confirm with the same original OfficeDeviceStore.save(current,title,result) one-revision CAS. Preview is owner-scoped in memory and fenced to exact namespace/document ID/revision/current body/title; a stale two-tab CAS refuses without partial editor replacement. Changing document/owner/privacy or typing a new draft clears staged content. Select an authentic heading and insert its source Markdown internal link at caret through the existing original textarea/input/autosave. No new writer, editor, IndexedDB, history schema, sync authority, or HTML parser.

Unit tests cover duplicate IDs, nested indentation, Unicode, artificial headings within fences, in-place TOC refresh and outside-source preservation, malformed marker refusal, safe cross-reference insertion and maximum body size.
